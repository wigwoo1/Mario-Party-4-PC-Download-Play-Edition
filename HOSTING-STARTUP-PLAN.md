## Implementation milestones

1. Reuse the existing private room service and measured public runtime allowlist. Resolve a usable public IPv4 using the existing router discovery where available. Format a free IP hostname; reject private, carrier NAT, loopback and reserved addresses using the existing native public-IP policy. A generated hostname is only a candidate, never evidence of reachability.
2. Manage HTTPS and direct reachability as an owned startup service. Acquire only this service's finite router mappings and firewall permissions. Do not replace another computer's existing port mapping. Two hosts on the same public IP must fall back or reuse a verified compatible service rather than overwrite each other. Validate certificate trust, correct runtime build identity and room service before offering the address. Keep certificate state across launches.
3. If direct startup fails within a bounded deadline, start an owned free fallback and obtain its actual HTTPS address. Cloudflare Quick Tunnels are an available account-free development option, but have no uptime guarantee and are explicitly for testing/development. Do not describe that option as a guaranteed production service. Do not add a paid subscription or require payment details. Supply and verify dependencies/licensing before distributing the launcher.
4. Give the verified service origin to the existing native automatic Host/Join flow. Preserve the current private room links, asset verification, shader receipts and 60-second signed reconnect rules. Changing an address must not silently restart a match or reset a recovery deadline. No private disc files, profiles, certificates or descriptor paths may become HTTP routes. Assets remain peer-to-peer.
5. Test direct success, blocked direct startup/fallback, missing tools, occupied ports, duplicate hosts, cancellation, process exits and owned cleanup. Then verify trusted HTTPS, asset transfer, actual gameplay and reconnect on the second desktop and Android cellular connection. A reachable website alone does not prove WebRTC connectivity or provide TURN relay service.
