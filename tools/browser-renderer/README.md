# Browser renderer and production runtime build

This CMake project builds Aurora GX/GPU and game/platform sources for WebAssembly. It includes standalone contracts for renderer/dependency checks and an opt-in `partyboard_browser_runtime` target. The production target links the browser game, renderer, UI, settings, audio, and platform archives. Configure `PARTYBOARD_OVERLAY_PACKAGE_DIR` with the complete compiled side-module directory to embed the 91 current overlays and build a production package.

Run `tools/build-browser-renderer.ps1` with `-EmsdkRoot`, `-Python`, `-Dependencies` (the populated native `_deps` directory), and a separate `-BuildDirectory`. Set `PLAYWRIGHT_MODULE` to the available Playwright package. The current tested SDK is Emscripten 6.0.10. The workspace Aurora browser/portability patches must already be applied (the native build helper applies them). To build and test the production package, also pass `-NodLibrary` and `-OverlayPackageDirectory`; the script then links `partyboard_browser_runtime` and runs the muted Edge package check. `-CacheDirectory` optionally places Emscripten's generated ports in a writable, short-path directory when the SDK's default cache is restricted.

Pinned dependency source trees are reused; PNG/zlib now come from Emscripten ports. No native binary libraries are linked into the browser artifact. Asyncify is required for the new browser startup and wait paths; the final game and side modules must be built consistently. On restricted Windows hosts, set `TEMP` and `TMP` to a writable short directory before building so Emscripten can remove its compiler scratch folders.

Artifacts include `libpartyboard_browser_renderer.a` and standalone contract pairs under target-specific directories. The renderer archive alone is compile evidence, not a game runtime.
`libpartyboard_browser_core.a` contains shared platform sources; standalone contracts cover narrower behavior than the production runtime. RmlUi and ImGui are compiled into the current runtime configuration.
`fmt`, Abseil containers, xxHash and SQLite now have WebAssembly build targets. A separate dependency contract exercises formatting, map storage, a hash golden value and an in-memory SQL query. SQLite uses single-thread mode and disables extension loading; persistent browser storage is not yet integrated.

ImGui core and SDL3/WebGPU backends also compile for the browser. A generated build-only backend copy selects the modern Dawn API used by emdawnwebgpu; native dependency sources remain untouched. ImGui drawing is not yet runtime-tested.

The `aurora-contract` executable links the actual core and renderer archives and verifies Aurora initialization/shutdown in Edge. It requires a 64 KiB Asyncify stack. Single-threaded browser builds skip the native pipeline-cache writer and its write queue; cache loading and pipeline creation remain enabled, but browser cache persistence is not implemented. This startup test does not render a game frame or load game assets.
The Aurora contract now also executes 12 frames with ImGui geometry and checks an opaque red canvas pixel before shutdown. Pixel capture occurs before yielding the final frame because WebGPU current textures expire across presentation. This validates a simple integrated draw, not game content or GX command translation.
The integrated contract also exercises actual GX initialization, direct vertices, matrix transforms, TEV raster color and a green quad, checking its center pixel alongside the ImGui overlay. Textured GX rendering and game content are not yet verified.
The integrated GX test additionally uploads a tiled 4x4 RGBA8 texture and verifies blue/yellow samples using nearest/clamped sampling, direct texture coordinates and TEV replacement. Other texture formats and cache invalidation are not covered.
The build produces `libpartyboard_browser_game.a` from the shared `GAME_FILES` list plus browser coroutines and deterministic clock/random helpers. `partyboard_browser_runtime` links that archive with browser renderer, UI, settings, audio, and platform libraries, then embeds the supplied 91-overlay package. Its muted Edge package test instantiates the Wasm wrapper without starting the game, validates the resolution export, and verifies every embedded side-module digest. It does not open a game disc or execute gameplay.
MusyX and the existing game audio/OS adapters also compile into browser archives. No audible output or MusyX initialization is verified; the hardware callback and mutex paths still need runtime integration.
Dolphin matrix/OS/PAD/SI implementations compile into a browser archive. The optional browser_game_link_audit target performs a strict game_main link and currently fails on missing platform implementations. It is excluded from normal builds and must not be run as a configured game launcher; see the validation report for unresolved symbols.
Actual asset byte-swapping, DOL lookup and version sources now compile into the game archive. The Aurora contract pulls in byte-swapping code and tests integer/float golden values; it still does not call game_main or read game assets.
The integrated contract now verifies an 8192-byte synthetic CARD create/write/read/close round trip in temporary browser storage. Persistent saves across reload or browser restart are not implemented or verified.
